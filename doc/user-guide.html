AMS Accounting Management System User Guide

This guide explains how to use AMS from initial setup through day-to-day accounting, approvals, reporting, and audit review. It is organized by role so each user can follow the steps that apply to their responsibilities.

Application type: Spring Boot and Thymeleaf web app Authentication: OAuth2 / Keycloak Primary modules: Admin, Finance Admin, Accountant, CFO, Auditor Generated: August 23, 2026

What AMS Does

AMS is an enterprise accounting and financial governance application. It supports organization and branch setup, chart of accounts administration, fiscal period control, journal entry processing, invoicing, payables automation, cash and bank reconciliation, fixed asset workflows, CFO approvals, trial balance generation, financial reports, budget monitoring, audit log review, and security event acknowledgement.

Governed Accounting

Create accounting records with structured status flows such as draft, submitted, approved, posted, rejected, paid, completed, closed, or locked depending on the transaction type.

Role-Based Workspaces

Users see the workspace for their assigned Keycloak group: admin, financeAdmin, accountant, cfo, or auditor.

Traceable Decisions

Key accounting and control changes are recorded through audit logs, approval histories, timestamps, and user attribution.

Access And Roles

Users sign in from the public landing page through Keycloak. After login, AMS checks the user's group claim and redirects the user to the correct workspace.

Role / Group Landing Page After Login Main Responsibility
/admin /admin/users Create users, enable or disable users, reset passwords, create groups, and assign users to groups.
/financeAdmin /financeAdmin/organizationSetup Set up organizations, branches, chart of accounts, fiscal periods, tax jurisdictions, module controls, and approval rules.
/accountant /accountant/manualJournal Record journals, invoices, payments, collections, bank reconciliations, fixed assets, and depreciation imports.
/cfo /cfo/approvalsHub Review and approve finance submissions, generate reports, review trial balance, and monitor budgets.
/auditor /auditor/auditLogExplorer Review audit logs, investigate security events, filter activity history, and acknowledge control events.
Important: Users must belong to the correct Keycloak group. A user without a recognized group may authenticate successfully but will not reach a role workspace.

End-To-End Operating Flow

The most reliable way to roll out AMS is to configure master data first, then open fiscal periods, then process transactions, then review and report.

  1. Admin creates users and groups. Create each user in Keycloak through AMS Admin and assign the correct role group.
  2. Finance Admin creates the organization. Add the legal entity, base currency, registration details, tax details, and active status.
  3. Finance Admin creates branches. Add operating branches under the organization for branch-level posting and reporting.
  4. Finance Admin configures accounting controls. Build the chart of accounts, tax jurisdictions, fiscal periods, approval rules, and module controls.
  5. Accountant creates operational records. Add customers, vendors, bank accounts, invoices, journals, payment runs, collections cases, and reconciliation data.
  6. CFO reviews approvals and reports. Approve or reject submitted journals, budgets, and reports, then generate financial statements and trial balances.
  7. Auditor reviews evidence. Filter audit logs and security events to confirm who changed what, when, and why.

System Administrator Guide

Workspace

Open /admin/users. This page manages Keycloak users and groups for AMS access.

Create A User

  1. Go to Admin > Users.
  2. Select the option to create a user.
  3. Enter first name, last name, username, email, password, and realm.
  4. Submit the form. AMS creates the user in Keycloak and returns to the user list.
  5. Assign the user to the correct group, such as /accountant or /cfo.

Manage User Access

  • Search users: Use the search field to locate a user by identifying information.
  • Enable user: Restores access for a disabled user.
  • Disable user: Suspends access without deleting the identity.
  • Reset password email: Sends the user a password reset email from Keycloak.
  • Delete user: Removes the user from Keycloak. Use only when the account should no longer exist.
  • Create group: Add a new Keycloak group if the organization needs a new access category.
  • Add or remove group: Changes the user's AMS role access.
Prefer disabling a user over deletion when audit traceability matters. Deleted users may be harder to reconcile against historical business records.

Finance Administrator Guide

Workspace Navigation

  • Organization Setup
  • Chart of Accounts
  • Fiscal Configuration
  • Module Controls

Primary Outcome

Prepare the financial structure that accountants and CFOs depend on. Most transaction pages require an organization, branch, active accounts, fiscal periods, and module settings.

Organization Setup

  1. Open /financeAdmin/organizationSetup.
  2. Create the organization with company name, legal name, registration number, tax ID, base currency, fiscal year start month, address, email, phone, and active status.
  3. Select the organization from the registered companies list.
  4. Add branches with branch code, name, address, city, state, country, postal code, phone, email, and active status.
  5. Review the branches table to confirm branch records are available for journal entry and reporting workflows.

Chart Of Accounts

  1. Open /financeAdmin/chartOfAccounts and select an organization.
  2. Create accounts with account code, account name, description, account type, account subtype, and normal balance.
  3. Use standard accounting account types: Asset, Liability, Equity, Revenue, and Expense.
  4. Review the account table for active status and account metadata.
  5. Edit accounts when names, descriptions, or classifications need correction.
  6. Deactivate accounts that should no longer be used for new postings.

Fiscal Configuration

  1. Open /financeAdmin/fiscalConfiguration and choose the organization.
  2. Create fiscal periods by entering year, quarter, start date, and end date.
  3. Use period status controls to close a period after accounting work is complete.
  4. Lock a period when postings should no longer change except through controlled adjustment processes.
  5. Create tax jurisdictions with tax type, tax rate or method, effective dates, and active status.
  6. Deactivate tax jurisdictions that should no longer be used.

Module Controls And Approval Rules

  1. Open /financeAdmin/moduleControls and select an organization.
  2. Initialize default modules if no module controls exist.
  3. For each module, set whether it is enabled, user configurable, approval required, audit trail enabled, notifications enabled, and subject to a maximum transaction amount limit.
  4. Use notes and configuration JSON for module-specific policy details.
  5. Create approval rules for transaction types and thresholds where review is required.
  6. Deactivate rules that should no longer route approvals.
Setup is complete when organizations, branches, accounts, fiscal periods, tax jurisdictions, module controls, and approval rules are visible for the selected organization.

Accountant Guide

Manual Journal

Create balanced journal entries, add debit and credit lines, submit for review, and post approved journals to the general ledger.

Invoicing And Payables

Manage customer invoices, purchase invoices, vendors, payment schedules, payment runs, supplier statements, and expense records.

Cash, Assets, Collections

Import bank statements, reconcile bank lines, manage receivables collections, review fixed assets, and import depreciation journals.

Manual Journal Workflow

  1. Open /accountant/manualJournal.
  2. Select an organization. AMS loads branches and chart of accounts for that organization.
  3. Create or select a journal.
  4. Enter the journal header: branch, journal date, and description.
  5. Add journal lines. Each line needs an account, debit or credit amount, optional department code, project code, branch code, narration, and sequence.
  6. Confirm total debits equal total credits.
  7. Save the journal, then submit it for approval.
  8. After CFO approval, post the journal to the general ledger.
  9. Review the generated general ledger entries from the journal view.

Purchase Invoice Workflow

  1. Open /accountant/purchaseInvoice.
  2. Select the organization and choose or create a vendor.
  3. Enter invoice number, vendor details, invoice date, due date, currency, line items, tax, and account mapping.
  4. Save the invoice as a draft.
  5. Use the posting action to move the invoice through submit, approve, and post when the current workflow permits it.
  6. Reject or correct the invoice if source details, line classification, tax, or account mapping are wrong.
  7. Record supplier payment when payment is made.
  8. Use aged payables and payment schedules to track open balances.

Payables Automation

  1. Open /accountant/payablesAutomation.
  2. Select the organization. AMS loads bank accounts, vendors, payment schedules, payment runs, forecasts, and supplier statements.
  3. Review payment schedules by date range or status. Use the due list to identify payable items due as of today or another selected date.
  4. Submit, approve, reject, hold, reschedule, or cancel payment schedules as needed.
  5. Create a payment run by selecting eligible schedule items and the payment bank account.
  6. Submit the payment run, approve it, then execute it when payments should be recorded.
  7. Use the cash requirement panel to estimate outgoing cash by date bucket.
  8. Create supplier statements and use auto-match to reconcile supplier statement lines to internal payables.
  9. Mark disputed supplier statement lines when vendor balances do not agree.
  10. Complete the supplier statement once all lines are matched, cleared, or disputed.

Customer Invoicing

  1. Open /accountant/customerInvoicing.
  2. Select the organization. AMS loads customers, chart of accounts, and tax jurisdictions.
  3. Create or select a customer.
  4. Enter invoice header information, invoice lines, tax details, due date, and receivables account mapping.
  5. Review credit compliance, accounts receivable impact, and GL mapping indicators.
  6. Create the invoice, send it, and post it to the general ledger.
  7. Record customer payments when cash is received.
  8. Use the open receivables and aged receivables view to monitor collection exposure.

Receivables Collections

  1. Open /accountant/receivablesCollections.
  2. Select the organization and review aging information.
  3. Generate collection cases from overdue receivables.
  4. Open a case to review customer, invoice, balance, due date, days overdue, and status.
  5. Assign the case to a collector when ownership is needed.
  6. Add collection activities such as calls, emails, notes, or follow-up actions.
  7. Create dunning notices for formal customer reminders.
  8. Create promises to pay with promised amount and promised date.
  9. Reconcile promises to pay against current payment status.
  10. Escalate serious cases or place the customer on credit hold when risk policy requires it.
  11. Release credit hold when the issue is resolved.
  12. Create and send customer statements for account-level communication.
  13. Close collection cases once the balance is resolved or no further collection action is required.

Cash And Bank Reconciliation

  1. Open /accountant/cashAndBank.
  2. Select the organization and bank account.
  3. Create or import a bank reconciliation by entering statement date, opening balance, closing balance, and a statement file.
  4. Review imported statement lines in the verification queue.
  5. Run auto-match to match statement lines against candidate general ledger entries by available matching criteria.
  6. For unmatched lines, open candidates and manually match the correct general ledger entry.
  7. Unmatch a line if it was matched incorrectly.
  8. Complete the reconciliation when all required lines are verified and the reconciliation is balanced.

Fixed Assets And Depreciation Journals

  1. Use /accountant/fixedAssets to review the fixed asset register, asset values, depreciation information, and asset status.
  2. Use the fixed asset page actions to add a new asset or export asset information when those controls are enabled in the environment.
  3. Use /accountant/depreciationJournals to import depreciation journals from an external fixed asset system.
  4. Upload the depreciation import file with external system, external batch ID, journal date, optional description, optional branch code, and auto-submit choice.
  5. Review import history for batch totals, source information, import status, and linked manual journal ID.
  6. Open the linked manual journal for review, submission, approval, and posting.

Chief Financial Officer Guide

Approvals Hub

Review submitted manual journals, inspect journal lines, approve valid entries, and reject entries with a reason.

Reporting

Generate trial balances and financial reports, save snapshots, submit reports, and approve or reject report versions.

Budget Control

Create budgets and lines, approve budgets, activate budgets, and review dashboard consumption and alerts.

Approve Or Reject Manual Journals

  1. Open /cfo/approvalsHub.
  2. Select the organization.
  3. Review the pending journal queue.
  4. Open a journal to inspect header details, branch, submitted user, total debits, total credits, approval rule, and all journal lines.
  5. Approve the journal if it is complete, balanced, properly supported, and posted to the correct accounts.
  6. Reject the journal when correction is required. Enter a clear rejection reason so the accountant can resolve the issue.

Generate Trial Balance

  1. Open /cfo/trialBalance.
  2. Select the organization and as-of date.
  3. Generate the trial balance.
  4. Review account codes, account names, debit balances, credit balances, and totals.
  5. Confirm total debits equal total credits.
  6. Save a trial balance snapshot when the report should be retained for audit evidence or period close records.
  7. Retrieve saved snapshots for the same report date when historical review is required.

Generate Financial Reports

  1. Open /cfo/financialReports.
  2. Select the organization and report period.
  3. Choose report type: Income Statement, Balance Sheet, Cash Flow Statement, Equity Statement, Budget Variance, or Custom Report.
  4. Generate the report. AMS can persist the generated report to report history.
  5. Review totals and line details.
  6. Submit a report for approval when it is ready for management review.
  7. Approve reports that are final and suitable for publication.
  8. Reject reports that require correction, including a reason.
  9. Use report history filters by type and date range to retrieve prior report versions.

Manage Budgets

  1. Open /cfo/budgetControl.
  2. Select the organization and year.
  3. Create a budget with name, year, period dates, and status.
  4. Add budget lines by account, amount, period, department, or other available dimensions.
  5. Submit the budget for review.
  6. Approve the budget when it is ready for use.
  7. Activate the budget so it can be used in budget control and spend monitoring.
  8. Review the budget dashboard for allocation, spend, remaining balance, utilization, variance trend, and alerts.

Auditor Guide

Audit Log Explorer

Search accounting activity by organization, entity type, entity ID, date range, user, and action.

Security Events

Review security events by severity, acknowledgement state, and date range. Acknowledge events after investigation.

Review Audit Logs

  1. Open /auditor/auditLogExplorer.
  2. Select the organization.
  3. Filter by entity type when investigating a class of records, such as journals, invoices, users, module controls, or fiscal periods.
  4. Filter by entity ID when investigating one exact record.
  5. Filter by start and end date to review activity for a period.
  6. Review old value, new value, action, user ID, IP address, user agent, description, and timestamp.
  7. Reset filters when starting a new search.
  8. Export filtered records to CSV when audit evidence needs to be shared or retained outside the application.

Review Security Events

  1. Open /auditor/securityEvents.
  2. Select the organization.
  3. Review unacknowledged events first.
  4. Filter by event type, severity, user, or date range when investigating a pattern.
  5. Open each event detail modal and assess the title, description, IP address, user agent, created time, severity, event type, and acknowledgement state.
  6. Acknowledge the event after investigation. AMS records the acknowledgement user and time.
  7. Export filtered security events to CSV when event evidence is required for compliance review.

Recommended Month-End Close Flow

  1. Confirm setup. Verify the period exists, is open, and has the required chart of accounts, branches, tax jurisdictions, and module controls.
  2. Post operational transactions. Ensure customer invoices, purchase invoices, expenses, payments, and manual journals are posted where applicable.
  3. Review payables and receivables. Run aged payables, aged receivables, collection cases, and supplier or customer statements.
  4. Reconcile banks. Import bank statements, auto-match, manually match exceptions, and complete reconciliations.
  5. Post depreciation. Import depreciation journal batches and post the linked journals after review and approval.
  6. Resolve approvals. CFO reviews pending journals, budgets, and financial reports.
  7. Generate trial balance. Confirm debits and credits agree. Save a snapshot for evidence.
  8. Generate reports. Produce income statement, balance sheet, cash flow, equity statement, budget variance, or custom reports.
  9. Audit review. Auditor reviews audit logs and security events for the close period.
  10. Close and lock period. Finance Admin closes the fiscal period, then locks it after final review.

Controls And Auditability

Control Area How AMS Supports It User Responsibility
Access control OAuth2 login and Keycloak group-based routing. Admin keeps user groups accurate and disables inactive users promptly.
Approval control Journals, budgets, financial reports, payment schedules, and payment runs support submit, approve, and reject actions. Approvers must review source details and give clear rejection reasons.
Posting control Journals and invoices create general ledger impact only after posting workflows are completed. Accountants should post only complete, approved, and balanced records.
Period control Fiscal periods can be created, closed, and locked. Finance Admin should close and lock periods after the month-end checklist is complete.
Audit trail Audit logs capture entity changes, users, timestamps, old values, and new values. Auditors should review exception patterns and preserve evidence for significant items.
Security monitoring Security events can be filtered and acknowledged. Auditors should prioritize unacknowledged and high-severity events.

Troubleshooting

Issue Likely Cause What To Do
User logs in but lands on the public page or cannot access a workspace. The user is not assigned to a recognized Keycloak group. Admin should assign the user to /admin, /financeAdmin, /accountant, /cfo, or /auditor.
Organization dropdown is empty. No organization exists or the user lacks permission to retrieve organization data. Finance Admin should create the organization. Confirm the user is authenticated.
Journal cannot be submitted or posted. Journal lines may be incomplete, unbalanced, missing accounts, or not in the required status. Review line details, debit and credit totals, journal status, and approval state.
Invoice does not post correctly. Missing customer or vendor, missing account mapping, missing line item data, or invalid tax setup. Verify master data, chart of accounts, tax jurisdictions, line totals, and status workflow.
Bank line has no match candidates. No matching general ledger entries exist for the date, amount, or account context. Confirm the related GL entry has been posted and review bank account mapping.
Financial report totals look incomplete. Transactions may remain in draft, submitted, or approved states but not posted. Post all approved accounting entries before generating final reports.
Period cannot be safely locked. Outstanding reconciliation, unposted journal, open invoice, or unresolved approval may remain. Run the month-end close flow and resolve open work before locking the period.

Glossary

Chart Of Accounts

The list of accounts used for accounting postings, grouped by account type such as Asset, Liability, Equity, Revenue, and Expense.

Fiscal Period

A defined accounting period with start and end dates. Periods can be closed and locked to control posting.

General Ledger

The official accounting record created by posted journals, invoices, expenses, payments, and other accounting events.

Manual Journal

A direct accounting entry with debit and credit lines. It must balance before it can be posted.

Aged Receivables

A report that groups unpaid customer invoices by how long they have been outstanding.

Aged Payables

A report that groups unpaid supplier obligations by due date or overdue age.

Payment Run

A batch of payable schedule items selected for payment, then submitted, approved, and executed.

Audit Log

A record of system activity showing the entity changed, action taken, user, old value, new value, timestamp, and technical request details.
